# 芯宝 Windows 桌面安装版设计

日期：2026-08-30  
状态：设计已确认，待实施计划

## 1. 目标与范围

本项目把 `IntelliChat-Platform-upload` 改造成面向普通 Windows 用户的安装版桌面软件。用户下载一个安装程序，安装后通过桌面快捷方式启动芯宝，不需要安装 Conda、Python、pip 或手工运行依赖/模型脚本。

首版目标平台为 Windows 10/11，硬件前提为 NVIDIA GPU，建议显存不低于 4 GB，并安装支持 CUDA 12.x 的 NVIDIA 驱动。DeepSeek API Key 继续由用户在前端设置页自行填写。`hardware_product` 不在本次范围内。

本次范围包括：运行时封装、桌面启动链路、安装/卸载/升级、用户数据目录、GPU 与模型检查、前端地址解耦、发布构建和干净机器验收。

本次不包括：硬件版本同步、Index-TTS 默认集成、跨平台支持、重写为 Qt 原生界面、替换 DeepSeek 服务、云端账号系统和自动更新服务。

## 2. 交付形态

最终交付物为 `Xinbao-Setup-v<version>.exe`，使用 Inno Setup 生成。安装包采用 one-folder 应用布局，不采用 PyInstaller one-file。原因是 CUDA/PyTorch、ChromaDB 和本地模型体积较大，one-folder 更容易启动、升级、定位 DLL/隐藏依赖问题。

普通用户只接触安装程序、桌面快捷方式和开始菜单入口。安装程序提供标准卸载入口。开发者脚本（`install.bat`、`download_models.bat`、`models_ready.bat`）仅用于构建/调试文档，不属于普通用户必经流程。

## 3. 运行时架构

### 3.1 内置运行环境

构建机使用官方 CPython 3.11.x 创建项目私有 `.venv`，并在其中安装锁定版本的 CUDA PyTorch 及项目依赖。发布包内置该 Python 运行时、`.venv`、项目代码、静态资源和本地模型。用户机器不需要预先安装 Python 或 Conda。

不直接复制开发机的 `pytorch_env`，避免 Conda 元数据、解释器绝对路径和不可迁移配置进入发布包。PyTorch CUDA 运行库随应用提供；NVIDIA 驱动仍由系统提供且必须满足版本要求。

### 3.2 启动流程

`Xinbao.exe` 负责以下步骤：

1. 解析程序目录和用户数据目录；
2. 检查 NVIDIA GPU、驱动/CUDA 可用性和建议显存；
3. 检查 embedding、reranker、路由分类器及知识库文件的存在性和校验值；
4. 选择空闲的本地回环端口；
5. 启动 Flask/Waitress 后端子进程；
6. 轮询健康检查接口，确认模型初始化完成；
7. 打开 pywebview 桌面窗口并加载本地服务地址；
8. 窗口关闭或启动器退出时，回收后端进程。

启动失败必须显示中文诊断信息，至少区分：无 NVIDIA GPU、驱动过低、显存不足、模型缺失/校验失败、端口不可用、后端初始化异常和网络/API 配置问题。错误信息写入用户数据目录下的日志，但不得写入 API Key 明文。

### 3.3 前后端地址

前端不得继续写死 `http://127.0.0.1:5000`。API、SSE 和音频地址统一使用当前页面 origin 的相对路径，或由启动器在启动时注入实际端口。后端继续只监听本机回环地址，避免无意暴露到局域网。

## 4. 用户数据与配置

安装目录（默认 `C:\Program Files\Xinbao\`）只保存程序、依赖、模型和只读资源。所有可变数据保存到 `%APPDATA%\Xinbao\`：

- `config.json`：用户信息、API Key、语音和应用设置；
- `chroma_db\`：长期记忆数据库；
- `uploads\`：用户上传内容；
- `static\audio\`：运行时生成的音频；
- `logs\`：启动、后端和错误日志。

首次启动时，如果用户配置不存在，则从无密钥模板创建；若 API Key 为空，前端自动突出设置入口。保存设置后调用后端连通性检查，并以可读错误提示无效 Key、网络不可达或服务限流。

升级安装必须保留 `%APPDATA%\Xinbao\`，不得覆盖 API Key、长期记忆和用户设置。卸载默认只删除程序文件；如需删除用户数据，提供单独且明确的“清除芯宝数据”操作。

配置中的路径全部使用相对路径或运行时解析后的路径，不得包含开发机绝对路径。日志、异常堆栈和诊断信息必须脱敏，不记录 API Key。

## 5. 安装器行为

Inno Setup 安装器负责复制 one-folder 应用、内置 `.venv`、模型和资源，创建快捷方式并注册卸载项。安装过程不访问 Conda，不调用用户系统 Python，也不要求联网下载依赖或模型。

安装器需要支持覆盖升级：先关闭旧版本进程，再替换程序文件；用户数据目录不参与覆盖。安装结束后可提供“立即启动芯宝”选项。安装包应附带版本号、构建时间、目标 CUDA/PyTorch 版本和 SHA-256 校验文件。

## 6. 构建流程

构建在干净的 Windows 构建机执行，避免把开发机状态当成发布依赖：

1. 从上传版本建立发布工作区，排除 `hardware_product`、个人报告、临时缓存和运行产物；
2. 安装 CPython 3.11.x，创建项目 `.venv`；
3. 使用锁定的依赖清单安装 CUDA PyTorch、Flask、Waitress、ChromaDB、sentence-transformers、pywebview 等依赖；
4. 将 embedding、reranker 和分类器放入发布目录，生成模型清单及 SHA-256；
5. 构建启动器和后端健康检查；
6. 生成 one-folder 应用目录；
7. 用 Inno Setup 生成 `Xinbao-Setup-v<version>.exe`；
8. 对安装包、关键 DLL、模型清单和启动入口做完整性检查；
9. 生成发布说明、系统要求、已知限制和 SHA-256 文件。

## 7. 测试与验收

### 7.1 自动化测试

保留并运行现有单元测试，新增以下覆盖：路径解析、用户数据迁移、动态端口、健康检查、GPU 检查、模型校验、进程回收、前端相对 API 地址、配置脱敏和安装器文件清单。

### 7.2 干净机器验收矩阵

- NVIDIA GPU + 合格驱动 + 联网：安装、首次启动、填写 API Key、流式聊天、RAG、语音；
- NVIDIA GPU + 合格驱动 + 断网：应用可打开，显示 DeepSeek/edge-tts 网络错误，不崩溃；
- 无 NVIDIA GPU：启动前给出明确不支持提示；
- 驱动过低或显存不足：显示可操作诊断信息；
- 端口被占用：自动换用空闲端口；
- 升级安装：API Key、设置和 ChromaDB 记忆保留；
- 卸载：程序删除，用户数据按明确操作决定是否清除；
- 异常关闭：后端进程不残留，下一次可正常启动。

验收标准是：普通用户在干净 Windows 10/11 机器上只需运行安装程序和桌面快捷方式即可进入芯宝界面；除填写自己的 DeepSeek API Key 外，不需要执行命令、安装依赖或下载模型。

## 8. 分阶段实施

### 第 1 期：运行时重构

完成路径与配置抽象、用户数据目录、相对 API 地址、健康检查、GPU/模型诊断和后端进程生命周期。

### 第 2 期：封装与安装器

完成 CPython + `.venv` 构建脚本、依赖锁定、模型清单、one-folder 产物、Inno Setup 脚本、快捷方式、卸载和升级策略。

### 第 3 期：验收与发布

在干净机器执行测试矩阵，修复打包遗漏和路径问题，补齐普通用户文档，生成安装包、校验文件和 GitHub Release 说明。

## 9. 风险与应对

- **安装包过大**：首版接受数 GB 体积；后续再评估模型拆包或按需下载。
- **PyTorch/CUDA DLL 缺失**：构建阶段运行真实 GPU 推理，并在干净机器启动验证。
- **venv 路径迁移问题**：在最终安装目录构建/复制后运行完整冒烟测试，避免依赖开发机绝对路径。
- **API Key 泄露**：公开配置只提供空值模板；日志和发布包扫描密钥模式。
- **edge-tts 依赖网络**：保留文本回复功能，语音失败时显示可理解提示并继续对话。
